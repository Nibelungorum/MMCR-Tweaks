# `mmcr:eco` Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` for inline execution, or `superpowers:subagent-driven-development` if delegation is requested. The checkboxes below track implementation, not design approval.

**Goal:** 一个 ME 通讯口带动结构中隔开放的原生 FD、FX，下一单并准确回传产物。

**Architecture:** MMCR 提供已匹配的形状。通讯口兼任 L4 主机，适配层仅负责集群归属和 AE2 节点之间的连接；工作线程和订单仍由 ECO 管理。

**Tech stack:** Java 21、Minecraft 1.21.1、NeoForge、MMCR、AE2、Neo ECO AE Extension。

## Global constraints

- 模组 ID `mmcr_tweaks`，机器 ID `mmcr:eco`。不发布测试形状，不硬编码生产布局。
- 对照 `reference/eco` 的 `21.2.19` 源码。GitHub 的 `21.2.19-beta` 是已发布的预发行包，不标成正式版；若用它跑测试，结果须注明版本。
- 不修改 MMCR、ECO 或 AE2LT 的源码；不注册另一套样板提供者、不提交第二份订单，不改 CPU 或规划器。

## 1. 注册机器、通讯口和仅供测试的结构

- [x] 在 `build.gradle`、`gradle.properties` 和 `src/main/resources/META-INF/neoforge.mods.toml` 声明依赖。允许指定本地 MMCR 构建产物，不依赖机器上的绝对路径。基线验证用 `../mmcr-1.21.1/gradlew -p . --offline --no-configuration-cache build`。
- [x] 在 `src/gametest/` 注册测试布局 `CPIFIX`：C 为控制器，P 为通讯口，I 为铁块，F 为 FD，X 为 FX。用 `RegisterMachineStructuresEvent` 注册到测试运行环境。断言结构成型、未摆 ECO 主机；首次运行应因缺少机器或通讯口而失败。
- [x] `EcoMachine` 通过 MMCR 的 `MachineDefinitionProvider` SPI 参与定义阶段，用 `RegisterMachineDefinitionsEvent.registerMachine` 注册机器和 tick 回调；`MMCRTweaks` 注册通讯口方块、物品、实体类型和 `AECapabilities.IN_WORLD_GRID_NODE_HOST`。给方块、物品和机器配资源名称；不给通讯口开放原生主机配置/结构建造 UI。
- [x] `EcoPortBlockEntity` 调用 `super(type, pos, state, ECOTier.L4)`；未绑定时不暴露 ME 连接面。运行 `build` 并检查发行 jar 不含测试形状。

## 2. 绑定指定实例，保持原生调度

- [x] 在同一测试结构放入普通合成样板，先断言 FD、FX、通讯口具有相同集群及 ME 网络，终端侧 `grid.getCraftingService()` 可见样板。重复成型通知后验证连接数不变；未接入时测试应失败。
- [x] `EcoSubsystem.tick(TickContext)` 从控制器的 `structureSnapshot().pattern().pattern().keySet()` 取已旋转的相对坐标，转为世界坐标；不枚举外接长方体。MMCR 的 `componentClaims` 不包含原生 ECO 实体，不能把它当 FD/FX 清单。
- [x] 绑定前验证恰好一个通讯口、至少一个 FD 和一个 FX、各实体节点均就绪且不属于其他集群。依次 `addBlockEntity` 收齐成员、绑定成员、为独立节点建立 `GridHelper.createConnection` 连接。记录本机创建的连接及实体身份；失败时撤销已完成步骤。已绑定且结构版本相同的 tick 不扫描形状。
- [x] 在原生计算器入口跳过当前已被认领实例的形状复检；其他原生 F 系列计算器判断候选成员时排除这些实例和自定义通讯口。只在本机持有 FD/FX 时屏蔽其物理接线面，避免绕过通讯口。
- [x] 使用普通 AE2 合成 CPU，在外网存入一份原料并提交一单普通样板。断言库存按配方扣料、产物数量准确、再过一段时间也不增加。相邻的其他 ECO 机器不参与这一单。

## 3. 区分断网、卸载和物理拆除

- [x] 测试拔掉通讯口外部线：原网络不再能通过该 FD 下单，重接后原样板可用；这条路径不调用 `breakCluster()`。
- [x] 按已绑定控制器和结构跨越的区块跟踪生命周期。MMCR 控制器 `resetMachine(boolean, boolean, boolean)` 使成型状态失效时清理本机绑定；区块/世界卸载时先无损解绑，避免依赖已停掉的机器 tick。清理要可重复执行。
- [x] 加载着的机器确实被拆坏时用 `NECraftingCluster.breakCluster()`；卸载用 `destroy()`，不清 FX 任务，不创建订单副本。拆/卸两条路径都只销毁本机连接、撤销本机认领。
- [x] 用验收布局拆掉一个铁块，保留 FD 和 FX，验证不能再接单；在 FX 收料后保存 NBT，走卸载回调并重建控制器、通讯口、FD、FX，验证只完成一次。此测试没有实际驱逐磁盘区块，也没有测试完整服务器重启。

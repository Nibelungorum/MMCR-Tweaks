# 第二版：MMCR 的终局 ECO 合成与计算子系统

保留第一版的 `mmcr:eco` 和 `mmcr_tweaks:eco_me_port`，将它升级为 F9 虚拟合成。另注册独立机器 `mmcr:eco_cpu`，通过一个计算通讯口 `mmcr_tweaks:eco_cpu_port` 提供 C9 极限 CPU。两台机器各自成型、各自接 ME 线，也可以接同一个 ME 网络。正式形状仍由用户提供；验收布局只进 GameTest，不进发行 jar。

## F 系列：免冷却，不免电

结构仍需一个合成通讯口、至少一个原生 FD 和一个原生 FX，位置不要求相邻。MMCR 判定成型后，本机直接获得 F9 虚拟合成能力，不检查原生组网的八主机、交换模块或最大长度，也不要求流体仓或冷却液。已放置的第一版通讯口沿用原方块 ID、实体类型和 ME 节点，不需要换块。

一个 FX 仍是一条物理通道。“无限”指一条通道一次可以处理同一配方的整批数量（以有符号 64 位为界），不是一条通道同时跑任意多种配方。沿用 ECO 下料、执行和回传路径。电力充足时，一批在首个工作 tick 完成；这不包括规划时间，也不保证输出网络阻塞时立即交货。保留 ECO 虚拟合成的工作费：本机每个有虚拟工作进展的 tick 支付一次 10,000,000 AE 基础费用，遵循 AE 用电倍率，不能按 FX 数重复扣。缺电时等待，不扣冷却、不退回低档，也不凭空出料。免冷却只作用于 MMCR 认领的机器。

## C 系列：一个通讯口实际承载订单

满足 MMCR 的结构规则且有一个计算通讯口，即可向 ME 网络公开一个可选择的空闲 ECO CPU。无需玩家摆放原生计算主机、线程核心、驱动器或晶阵。总合成存储为 `Long.MAX_VALUE` 字节，线程和并行为 `Integer.MAX_VALUE`。可用存储要扣除在途订单的实际预留；极限值不能导致扣账、求和或比较溢出。

空闲 CPU 是网络发现入口，不是运行中订单。接单后，计算通讯口为该单建立实际执行槽，用原生 ECO CPU 逻辑派单、接收产物及取消任务。只为实际订单分配和保存状态；不能预建 `Integer.MAX_VALUE` 个对象或沿用单个原生核心固定 64 槽的限制。任务完成、取消且库存已结清后回收槽位。计算通讯口持久化 CPU 状态，FX 仍负责自己的执行状态，不复制订单或重复投料。

新网络默认接受玩家及自动化请求。计算面板的**深度规划模式、循环规划、ECO 快速规划**三个开关默认开启；工具栏的智能翻倍保持 ECO 原生默认。已配置过的网络按 ECO 自己的设置同步，不因接入新通讯口、结构复检或重载而覆盖用户选择。

## 生命周期和适用范围

- 只有完整成型且在线的机器才对外提供相应服务。拔线与卸载不是物理拆机；区块卸载时释放运行时绑定，保存执行状态，重建后继续原单。
- 拆坏结构后停止接新单。取消和退回已扣材料沿用 ECO 的所有权规则；不得把持有库存的 CPU 当成空槽直接删除。
- 不改玩家原有的 ECO 主机、原版 AE2 CPU 或 AE2LT 规划器，不更改全局能耗或冷却配置，不重写 ECO 调度器。

## 验收

1. **一批而非多批。** 两台 MMCR 机器各有一个通讯口；F 系列只有一个 FD 和一个 FX，网络中没有其他 CPU，也没有流体仓。备好 513 个橡木原木，申请 2,052 个橡木木板。确认 C 系列接单、F 系列以一批执行 513 次合成，耗材与交付数量精确；不能以多批最终产量正确代替验证。
2. **只豁免冷却。** 空冷却、足电可以推进；电力不足不出料，恢复供电后原单只完成一次。同一台机器两个活跃 FX 在同一 tick 不重复收取虚拟工作费。
3. **顶配不是面板数值。** 验证 C 系列公布的上限、接单后可用字节减少和结束后释放。用同一计算通讯口保留 65 个小型待完成订单，证明并发不受单枚原生 C9 核心的 64 槽限制。
4. **恢复和隔离。** 在 CPU 或 FX 已收料时保存、卸载并重建实体，验证恰好一次交付；拆除计算结构后不能再接单。验证新网络的三项默认值和已有网络设置不被覆盖。保留第一版非相邻 FD/FX、拔线、拆机回归测试。
